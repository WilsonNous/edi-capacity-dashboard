# EDNNA — Escola Contínua

## Princípio

A EDNNA permanece matriculada enquanto a operação existir. Aprendizado não é um evento isolado: é um ciclo operacional permanente.

**Estudo → Prova → Professor → Homologação → Trabalho → Revisão da matéria → Novo aprendizado**

## Papéis

- **EDNNA:** estuda históricos, identifica padrões, propõe conhecimento, executa somente o que estiver homologado/autorizado e sinaliza divergências.
- **Equipe EDI / professores:** melhora a qualidade dos chamados, corrige inferências, registra exceções, homologa conhecimento e descreve como resolveu checkpoints humanos.
- **Redmine:** funciona como biblioteca operacional e trilha de evidências.

## Invariantes de governança

1. Histórico é evidência; não é autorização.
2. Inferência é aprendizado; não é regra de produção.
3. Nenhuma descoberta histórica pode se auto-homologar.
4. Conhecimento homologado deve ser revisável e versionado.
5. Divergência operacional deve provocar reestudo, nunca alteração silenciosa da regra.
6. Checkpoints humanos devem permanecer explícitos até existir integração segura e homologada.
7. Quanto melhor a qualidade do chamado, melhor o material de aprendizagem.

## Linguagem da Central de Aprendizagem

A interface pode usar a metáfora escolar para tornar o processo compreensível sem esconder seu significado técnico:

- Em estudo = procedimentos em aprendizagem.
- Prova = simulação/backtest contra históricos.
- Professor = operador autorizado a revisar/homologar.
- Matéria homologada = conhecimento aprovado para o escopo autorizado.
- Revisão da matéria = revalidação periódica contra operação recente.
- Preciso do professor = checkpoint/decisão humana.
- Caderno = chamado/evidência histórica.

## Revisão periódica

Política inicial de referência: **30 dias** para conhecimento homologado. A periodicidade deverá ser persistida por regra/player em evolução posterior. O reestudo não deve alterar automaticamente a regra ativa: diferenças devem gerar uma proposta de revisão para decisão humana.

## Qualidade para aprendizado — próxima evolução

Criar indicador por chamado para verificar se há material suficiente para ensinar a EDNNA, considerando ao menos:

- cliente e player identificados;
- dados estruturados necessários ao procedimento;
- Blueprint/participantes/contatos quando aplicável;
- procedimento executado;
- comunicações enviadas e recebidas;
- evidências/anexos;
- resultado obtido;
- conclusão registrada.

Chamados incompletos devem gerar orientação objetiva sobre o que falta para se tornarem bons materiais de aprendizagem.
